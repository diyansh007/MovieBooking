DESIGN PATTERNS

Pattern Demonstration

Try the actions below to see the newer patterns participate in real booking and draft workflows.

Live pattern walkthrough

  1. Open Book Ticket, choose a pricing policy, and watch the server-calculated quote update. Confirm a booking to run the Builder, Mediator, Template Method, Chain, DAO, and Observer flow.
  2. Book 4 or more seats to select the group workflow; use the Group Discount policy to see its eligibility rule in the quote.
  3. Open Your Bookings and choose Book Again. The Prototype creates a new pending draft with no original booking ID; edit it and confirm to create a separate booking.
  4. On the booking form, choose Save draft state, change movie/format/seats/policy, then choose Undo last change to restore the saved Memento snapshot.

Factory

Definition: Creates concrete movie implementations without exposing creation logic.

Classes: MovieFactory, TwoDMovie, ThreeDMovie, ImaxMovie

Used in: booking form creates the movie selected by format.

Singleton

Definition: One shared instance coordinates the system.

Classes: BookingSystem

Used in: all real booking actions flow through the shared booking coordinator.

Chain of Responsibility

Definition: Each handler validates one step and passes the request forward.

Classes: SeatAvailabilityHandler, PaymentHandler, TicketConfirmationHandler

Used in: seat check → payment verification → ticket confirmation.

Observer

Definition: Subscribers react to successful booking state changes.

Classes: BookingSubject, CustomerNotifier, AdminNotifier, ManagerNotifier

Used in: after a booking is persisted successfully, observers receive notifications.

Template Method

Definition: A fixed workflow plus variable hooks for different booking types.

Classes: BookingWorkflowTemplate, StandardBookingWorkflow, GroupBookingWorkflow

Used in: sequence: prepare → validate → persist → notify → finalize.

Strategy

Definition: Interchangeable pricing arrangements.

Classes: PricingStrategy, StandardPricingStrategy, StudentDiscountStrategy, WeekendPricingStrategy, GroupDiscountStrategy, PricingService

Used in: booking form selects policy, backend calculates authoritative total.

Builder

Definition: Step-by-step construction of valid booking objects.

Classes: BookingBuilder, ConcreteBookingBuilder, BookingDirector

Used in: booking request created with validated user, movie, format, seats, amount, and strategy.

Prototype

Definition: Clone an existing booking into a separate editable draft.

Classes: HistoryController, BookingMediator, MovieBookingMediator, BookingPrototype, BookingDraft

Used in: Book Again loads the source booking through the authenticated DAO lookup, clones it with a fresh unsaved identity and pending state, and prefills the form. The source record remains unchanged.

Mediator

Definition: Coordinates collaborators without making the HTTP controller perform each operation itself.

Classes: BookingController, HistoryController, BookingMediator, MovieBookingMediator

Used in: the live booking request is routed through the mediator, which coordinates factory creation, pricing, Builder construction, and workflow selection. Book Again also goes through the mediator to create its prototype draft. Persistence, validation chain, and observer broadcasts remain in their own collaborators.

Memento

Definition: Save and restore prior draft state.

Classes: BookingDraft, BookingDraftMemento, BookingDraftCaretaker

Used in: Save Draft State and Undo Last Change recover the previous form state.

MVC

Definition: Separate domain data, controller logic, and view interaction.

Classes: model package, controller package, web files

Used in: routes delegate business operations to controllers while HTML/JS render the user interface.

DAO

Definition: Encapsulates persistent database access.

Classes: UserDAO, BookingDAO

Used in: user authentication, booking storage, retrieval, and cancellation all go through the data access layer.
